# Puppy

一只悬浮在桌面上的像素小狗,实时反映 iTerm2 里各个 Claude Code session 的状态。
双击它展开列表,点列表里的某一行就跳到对应的 iTerm2 窗口 / 标签页。

没有系统通知,没有声音 —— 所有提醒都靠小狗自己的表情和动作。

## 用起来

```bash
make run      # 构建 .app、签名、启动(会先杀掉已在跑的实例)
make stop     # 退出
```

小狗没有 Dock 图标,**右键小狗**是唯一的退出入口。

### 怎么支使它

| 操作 | 结果 |
|---|---|
| **单击** | 换窝:蹲到当前屏幕的下一个角(右下 → 左下 → 左上 → 右上 → …) |
| **双击** | 展开 / 收起 session 列表 |
| **拖动** | 放到任意位置 |
| **右键** | 展开列表 / 刷新 / 回到默认位置 / 退出 |

挡住东西的时候不用瞄准拖 —— 点一下就扒拉到隔壁角去了,位置都会记住。被拖到半空中时,第一下单击是先归位到最近的角,再往下轮转。

双击的第一下会先跳一格,列表打开前它自己会跑回来。

### 小狗在说什么

| 样子 | 意思 |
|---|---|
| 闭眼呼吸 + 飘 `z` | 全部空闲,或者一个 session 都没有 |
| 小跑摇尾 | 有 session 在跑 |
| 睁大眼睛上下跳 + 红色 `!` | **有 session 在等你**(输入 / 权限确认) |
| 张嘴蹦跶 + 左上角绿色 `✓` | 刚有一轮任务跑完,而且别的都闲着(10 秒) |
| 右上角绿色 `✓` 徽标 | 刚有一轮任务跑完,但还有别的 session 在跑 / 在等你(10 秒) |

身体动画的优先级是 `等待 > 运行 > 刚完成 > 睡觉`,所以只要有任何一个 session 卡在等你,小狗一定在跳。

「刚完成」不参与这个优先级竞争 —— 它是挂在**右上角的独立徽标**。并行开好几个 session 时,A 跑完的那一刻 B 多半还在跑,身体得继续小跑,完成提示就单独冒在右上角,不会被吃掉。徽标和红色 `!` 分居左右两角,可以同时出现。

session 跑完顺手退出 claude 也没关系:完成记录只按时间窗淘汰,不跟着进程走。

### 气泡栈

光靠头顶 6pt 的符号太容易漏,所以需要你动手的事会**摞在小狗旁边**,一件一条:

```
╭──────────────────────╮
│ ✋ agentic-research   3m │   ← 等最久的贴着小狗
│ 在等你 · permission prompt │
╰──────────────────────╯◀ 🐶
```

这摞东西是**当前状态的直接映射**,不是一串会过期的通知:

```
栈 ≡ { session | 在等你 } ∪ { session | 刚跑完(60 秒内) }
```

- **不会被顶掉**:三个 session 同时等你就是三条,不轮播、不排队、不互相覆盖。
- **只跟真实状态走**:你在那个终端敲了回车,那一条自己消失;没处理完就一直挂着 —— 没有「已读」按钮,所以不可能出现「关掉了但其实忘了处理」。「跑完了」那种没有后续动作,跟着列表里的 ✅ 一起 60 秒后自消。
- **等最久的贴着小狗**,往上依次递减。处理完最紧急的,下一个自动滑到狗嘴边。
- 最多 5 条,再多折成一条 `还有 N 个 ›`,点它开完整列表。
- 「已等 40m」是分钟级的 —— 秒级要一个 1Hz 时钟,而这是个 24 小时挂着的窗口。
- **点一下** = 跳到那个 session 的 iTerm 窗口(跟点列表里的行一样)。注意跳过去**不会**让它消失,你没真回答它就还在。
- 默认开在小狗左边,左边挤不下就翻到右边;点开列表面板时整摞让位(列表里本来就都有)。没有系统通知、没有声音。

### 命令行(调试用)

```bash
make list                    # 打印当前 session 表
make watch                   # 持续打印状态变化(FSEvents 驱动)
./.build/debug/Puppy --focus <pid>    # 单独验证 pid → tty → iTerm2 跳转
./.build/debug/Puppy --render <dir>   # 把每个状态的每一帧渲染成 PNG
```

## 一次性设置:签名证书

默认退回 ad-hoc 签名,能跑,但**每次重新编译签名指纹都会变**,导致
「Puppy 想控制 iTerm2」的授权反复失效 —— 每次点 session 行都要重新授权一次。

建一个自签证书就能一劳永逸:

1. 打开「钥匙串访问」→ 菜单「证书助理」→「创建证书…」
2. 名称填 `puppy-dev`,身份类型「自签名根证书」,证书类型「代码签名」
3. `make run` 重新构建 —— 脚本会自动认出它并用它签名

第一次点某个 session 行时,系统会弹一次 Automation 授权,同意即可。
如果误点了拒绝,Puppy 会把你送到「系统设置 → 隐私与安全性 → 自动化」。

## 它是怎么知道的

Claude Code CLI 自己维护一份实时注册表:`~/.claude/sessions/<pid>.json`,
每个运行中的 CLI 进程一个文件,进程退出文件就没了。Puppy 只读这个,
**不碰** `~/.claude/projects/` 下的 transcript(那些能有十几 MB)。

注册表里没有「完成」这个状态。`busy → idle` 的转变就是一轮任务跑完了 ——
这是 Puppy 唯一推导出来的状态,其余全部直读文件。

跳转链路是 `pid → ps -o tty= → iTerm2 AppleScript 里匹配 session 的 tty`。
tmux / ssh / 非 iTerm 终端里的 session 拿不到匹配的 tty,这时候只把 iTerm 提到前台。

### 省电

用户明确要求过事件驱动而非轮询,所以:

- **FSEvents** 监听 `~/.claude/sessions/`,`latency=0.3s` 让内核合并连续写入。
  回调不解析事件内容,只当作「该重扫了」—— 目录里全是几百字节的小 JSON,
  整个重读是幂等的,原子写 / rename / 事件合并这些边缘情况因此全都不用管。
- 只监听 `sessions/` 这一层。FSEvents 是递归的,往上监听 `~/.claude` 会把
  transcript 的疯狂写入变成唤醒风暴。
- 30s 低频兜底重扫,配大 leeway 让系统能把唤醒合并掉。
- 「完成」徽标和庆祝动画的到期时刻各排一发**一次性**定时器,不是每秒轮询。
- 列表里「已等待 X 分钟」的 1s 时钟只在面板打开时存在。
- 小狗窗口被完全遮挡时停掉动画。

实测:全空闲时 **0% CPU**;有 session 在跑、小狗在动时约 3%(和帧率无关,
是 SwiftUI 动画循环的固定开销)。

## 已知的坑

- **注册表 schema 没有文档**(`peerProtocol:1`),可能随 CLI 版本漂移。
  所以解码全字段 Optional、未知 status 降级成中性态、单个文件坏掉不影响其余、
  目录不存在就显示「无 session」。已经见过计划里没列的 `shell` 状态。
- 文件被截断重写的瞬间可能读不出来。这时短暂沿用上一次的好数据(3s),
  否则列表会闪一下 —— 这是实测踩到的。
- nonactivating panel 永远拿不到键盘焦点,所以面板是纯点击交互。
